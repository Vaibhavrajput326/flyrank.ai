Content Refresh & Traffic Decay Opportunity Scoring Engine

Author: Vaibhav Rajput | Track: FlyRank ML Internship Capstone | Lane: Refresh / Content Opportunity Scoring

Title & Abstract

Question: How can machine learning reliably predict organic search performance drops and prioritize content refresh candidates across enterprise client domains?

Method: We formulated content decay prediction as a binary classification task on daily Search Console performance vectors, employing DuckDB aggregations and a Random Forest classifier evaluated under an honest grouped client split (GroupShuffleSplit).

Result: The Random Forest model achieved a 0.9083 ROC-AUC and 0.8310 F1-Score on unseen client domain holdouts, outperforming rule-based heuristics by over 3x in precision and eliminating naive split inflation.

1. Introduction / Problem Statement

Managing large-scale web properties involves monitoring thousands of published pages where manual audit is cost-prohibitive. Content decay—loss of impressions, clicks, or ranking position over time—severely degrades organic traffic if left unaddressed. This work provides a decision-support heuristic to automate the ranking and identification of pages requiring optimization, snippet updates, or full content rewrites before severe position decay occurs.

2. Data Contract & Preprocessing

Analysis was executed using DuckDB querying over the FlyRank ML Internship Warehouse (fact_content_daily_performance datasets) partitioned by month.

  • Observation Window: Aggregates from month 2026-03 (9,841,378 daily grain records across 55 active clients).
  • Unit of Analysis: Daily performance vector for a distinct content_hash_id and client_hash_id.
  • Target Definition: Binary label is_declining_label derived from trend directional drop indicators.
  • Excluded Features: Future traffic windows (month > 2026-03), raw domain strings, private URL identifiers, and target-derived columns (trend_direction, trend_pct) to strictly eliminate leakage.

3. Methodology & Validation Design

To eliminate client-level structural data leakage (domain authority memorization risk), we implemented a strict Grouped Client Split (GroupShuffleSplit / GroupKFold) ensuring 0% client overlap between training and validation sets.

Baseline vs. Machine Learning Model

  • Baseline Model: Heuristic rule engine flagging high-impression pages with sub-optimal position/CTR ratios.
  • Primary Model: Random Forest Classifier (100 estimators, max depth 10) leveraging numerical feature vectors including historical clicks, impression change, and click-through rate velocity.

5. Limitations & Honest Framing

  • False Positives (14.92%): Over-flagging occurs primarily on volatile or seasonal search queries where short-term keyword variance mimics early content decay.
  • False Negatives (4.76%): Missed drops occur predominantly on long-tail, low-volume pages where low baseline traffic yields insufficient statistical signal.
  • Honest Framing: All model outputs serve strictly as measured directional decision-support heuristics. They do not represent causal proof of Google search algorithm mechanics.
